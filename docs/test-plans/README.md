# docs/test-plans/

One test plan per release or major feature. Name files `<release-or-feature>-test-plan.md`
(e.g. `2026-q3-fee-approval-v2-test-plan.md`).

Each plan should state: scope, out-of-scope, environments, entry/exit criteria, suites to run
(link to actual `tests/` folders), risk areas, and sign-off owner. Keep plans short enough that
someone will actually read them before a release — link to detail (digest, traceability matrix)
rather than duplicating it.
